# CLAUDE.md

## О проекте
**Бот мама** – Telegram‑бот, написанный на Python с использованием библиотеки **aiogram**. Он предназначен для организации записей на тренировочные занятия (пример: волейбольные тренировки). Бот позволяет пользователям:
- записываться/отменять участие (кнопки «Я иду», «Я не иду»);
- добавлять/удалять друзей (муж/дев) через инлайн‑клавиатуру;
- просматривать текущий список участников;
- получать статистику и список пользователей (для администраторов);
- управлять блокировкой/разблокировкой пользователей.

## Техническое окружение
- **Python 3.x**
- **aiogram 2.x** — Telegram-бот (`main.py` написан под API aiogram 2: `FSMContext`, `executor`, `aiogram.contrib`).
- **maxapi** — клиентская библиотека для мессенджера **MAX** (`max_main.py`); требует **pydantic v2**.
- **ВАЖНО: конфликт зависимостей** — aiogram 2.x требует pydantic v1, maxapi требует pydantic v2, поэтому боты не могут жить в одном интерпретаторе и запускаются **двумя отдельными процессами** (см. `run_both.py`).
- **asyncio**, **aioschedule** — планировщик периодических задач (свой в каждом процессе).
- **SQLite** — две общие базы, доступ из обоих процессов. Базы переведены в **WAL-режим** (читатели не блокируют писателей), `busy_timeout=15с`; все SELECT читаются через `fetchall()` — незакрытый курсор с `fetchone()` держит shared-lock навсегда и вешает базу для чужих процессов. **Не открывать базы в DB Browser for SQLite при работающих ботах** — он держит блокировку записи:
  - `sbor.db` — временная таблица с участниками и их друзьями.
  - `database.db` — основная таблица `Users` (id, username, first_name, gender, block).
- **logging** — лог в файл `bot.log` (общий, режим добавления).
- **pytz** — часовой пояс `Asia/Yekaterinburg`.

| `sbor.db` | SQLite-файл, содержит таблицу `sbor` (участники и их друзья). |

## Основные функции (Telegram и MAX)
- **Регистрация пользователя** – при `/start` вызывается `active.add_user`: Telegram-бот пишет ID в `id_tg` (+username), MAX-бот — в `id_max` (username в MAX отсутствует).
- **Запись на тренировку** – обработчики `buy1` (callback `Я иду`) добавляют запись в `sbor.db` через `utils.add`.
- **Отмена записи** – `not_going` удаляет запись из `sbor.db`.
- **Управление друзьями** – кнопки «+ Мужчина», «- Мужчина», «+ Девушка», «- Девушка» добавляют/удаляют записи вида `Муж (Имя)`.
- **Админ‑панель** – команды `/admin`, `/admin1` открывают набор кнопок для администраторов (сброс таблицы, список функций, блокировка, разблокировка и т.п.).
- **Блокировка** – функции `add_user_to_block`, `check_user_in_block`, `unlock_users` управляют полем `block` в `Users`.
- **Планировщик** – `scheduler()` задаёт периодические сообщения о начале сбора, списке участников и финальном напоминании об оплате.
- **Оплата** – после финального сообщения админам отправляется личное сообщение с кнопкой «💳 Оплатить», после нажатия бот отправляет подтверждение.

## Настройка и запуск MAX-бота
1. Создать бота в MAX (у @masterbot), токен вписать в `config.py` -> `API_MAX`.
2. Добавить бота в групповой чат MAX и написать ему в личку.
3. Запустить `python get_max_chats.py` — скопировать `chat_id` группы в `GROUP_ID_MAX`, ID админов в `admins_max` (заполнено: 6253291, 6276257).
4. Запуск: `python max_main.py` (соло) или `python run_both.py` (оба бота с автоперезапуском).
5. Команда `/myid` у MAX-бота показывает ID пользователя (для `pol_max`).

## Как запустить оба бота одновременно
```bash
# Актуальная схема: два окружения на одном хостинге
TG_PYTHON=/путь/venv_tg/bin/python MAX_PYTHON=/путь/venv_max/bin/python python run_both.py

# Или вручную двумя процессами (systemd/screen/nohup):
python main.py      # окружение с aiogram 2.x (pydantic 1)
python max_main.py  # окружение с maxapi (pydantic 2)

# Одно окружение сработает только после порта main.py на aiogram 3:
python run_both.py
```

## Правила подтверждения действий
Для большинства операций (чтение, изменение файлов, запуск кода) подтверждения не требуется.

**Исключение** – удаление файлов. Любое удаление файлов требует явного подтверждения от пользователя.

### Дополнительные ограничения
1. **Ограничение автокоммитов** – автоматические коммиты без явно заданного сообщения запрещены; каждый коммит должен содержать осмысленное сообщение.
2. **Требовать ревью перед удалением** – любые команды, удаляющие файлы (`git rm`, `rm`), должны проходить предварительный код‑ревью или согласование.
3. **Лимит на количество изменённых файлов** – если в одном коммите более 7 файлов, требуется дополнительное подтверждение.
4. **Требовать указание авторов** – каждый коммит обязан включать строку `Co‑Authored‑By:` при совместной работе.
5. **Запрещённые паттерны в файлах** – запрещено коммитить строки, содержащие `password`, `secret`, `api_key` и т.п.; такие файлы отклоняются.
6. **Автоформатирование** – перед коммитом необходимо запускать `black`/`ruff` (или аналогичный линтер) и убедиться, что нет ошибок стиля.
7. **Подтверждение после удаления ветки** – удаление ветки (`git branch -d`) требует явного согласования.
8. **Запрет на force‑push** – `git push --force` запрещён без крайней необходимости и отдельного одобрения.

## Публикация в GitHub
Для того чтобы закоммитить и отправить проект в репозиторий GitHub, необходимо выполнить несколько шагов:
1. Инициализировать локальный репозиторий:
   ```bash
   git init
   ```
2. Добавить удалённый репозиторий (URL вашего репозитория):
   ```bash
   git remote add origin https://github.com/artem2012kf/MamaBot.git
   ```
3. Добавить файлы и создать первый коммит:
   ```bash
   git add .
   git commit -m "Initial commit"
   ```
4. При наличии персонального токена доступа (PAT) с правами `repo` выполнить push:
   ```bash
   git push -u origin master
   ```
Если токен не передан, push необходимо выполнить вручную после того, как вы добавите токен в настройки git (например, через `git config --global credential.helper store`).

## Правила поведения Claude
1. Claude всегда отвечает на русском языке.
2. Claude не запрашивает подтверждение при чтении файлов.
3. Claude может автоматически выполнять `git add .` и `git commit -m "msg"` без подтверждения, если в изменениях нет конфиденциальных данных.
4. Claude использует только инструменты, перечисленные в `CLAUDE.md` (Bash, Git, Edit, …). Любой запрос на сторонний сервис требует отдельного одобрения.
5. Claude не выводит сообщения‑подтверждения типа “Ok, делаю X”, а сразу сообщает результат.
6. На все Bash‑команды автоматически ставится тайм‑аут 5 секунд, если не указано иначе.
7. Claude не предлагает использовать интерактивные команды (`git rebase -i` и т.п.), так как они не поддерживаются.
8. Claude не использует `git push --force` без явного подтверждения пользователя.
9. Claude проверяет `.gitignore` перед добавлением файлов; если файл игнорируется, выводит предупреждение вместо принудительного `-f`.
10. Claude требует подтверждения перед удалением ветки.

11. Claude не задаёт уточняющих вопросов; если запрос ясен, сразу приступает к реализации без дополнительных подтверждений.
